The Setup

Here's how the game works

  • 🔓 Everyone owns a padlock they hand out to anyone who asks.
  • 🗝️ Everyone also owns a secret key that never leaves their pocket.
  • 💼 A briefcase locked with someone's padlock can only be opened by that person's key — not by the padlock, not by anyone else.
  • 🥷 Eve can see every briefcase that crosses the channel. Watching isn't the same as opening.

The Concept

This is Public-Key Cryptography

The padlock was a public key. The secret key was a private key.

Only a matching private key can open what a public key locks — never the public key itself, never anyone else's key. Run it backwards and you get a digital signature: sign with your private key, and anyone can check it with your public key.

🔓 Public Key

Shared with anyone.
Encrypts, or verifies a signature.

↔
🗝️ Private Key

Known only to the owner.
Decrypts, or creates a signature.

🔑 Symmetric

  • One shared key, fast
  • Needs a safe way to exchange it first

🔐 Public-Key

  • Two linked keys, no pre-shared secret
  • Slower, so often used just to swap a symmetric key

It's what powers the padlock in your browser (HTTPS), app logins, and digital signatures.

Put Public-Key Cryptography to the test

Five exercises, each a step harder than the last.

1. Which key encrypts?

Easy

You want to send Priya a private message. Which key should you use to encrypt it?

2. Match the action to the correct key

Easy–Medium

For each action, pick whose key — and which type — is used.

3. Compute n and φ(n)

Medium

Given primes p = 5 and q = 11, compute n = p×q and φ(n) = (p−1)(q−1).

4. Find the private exponent

Medium–Hard

Using n = 55, φ(n) = 40, and public exponent e = 3, find d such that e×d ≡ 1 (mod φ(n)), where 1 < d < 40.

Try each candidate d from 2 upward and test whether (3 × d) mod 40 equals 1.

5. Secrecy vs. proof of identity

Hard

Encrypting keeps a message secret. Signing proves who sent it. Describe how you'd combine both so a message is secret and verifiably from a specific sender.

Sign first with your private key, then encrypt the message-plus-signature with the recipient's public key. They decrypt with their private key (secrecy) and verify the signature with your public key (authenticity).
