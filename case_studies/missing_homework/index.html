Chapter 5 · The Method

How the search really worked

Here's the strategy you were using the whole time, with a name and a shape.

🌳

You Discovered: Depth-First Search (DFS)!

That's exactly the habit you built by hand while hunting for Homework.pdf:

  • Step into a folder, then immediately step into the next one inside it, as deep as you can go.
  • Hit a dead end (an empty folder)? Back out exactly one step.
  • From there, try the next unopened folder, going deep again before drifting sideways.
  • Repeat until you find what you're looking for, or there's nowhere left to check.

That strategy has a name: Depth-First Search. It always commits to one path fully before backtracking to try another.

📚 Why a Stack?

DFS remembers where to go next using a stack, a pile where you can only add or remove from the top. Every time you open a folder, it gets placed on top of the stack. When you hit a dead end, you pop the top folder off and land back on the one below it, exactly the folder you'd expect to return to.

Try it yourself: each push opens the next folder on the real path to Homework.pdf, then pop it to back out, exactly like the search you just ran.

🔑 Key Learnings

🧭
The Strategy

Go as deep as possible down one path before trying another, commit fully, and only backtrack once you truly hit a dead end.

📚
The Stack

The last folder you opened is the first one you return to. That "last in, first out" order is exactly what a stack gives you.

✅
Why It Works

Backing out exactly one step (instead of starting over) means you never skip a folder and never waste time re-checking one.

🌍
Where You'll See It

File explorers, maze-solving, puzzle games, web crawlers, and countless programming problems all lean on this exact idea.

Chapter 6 · New Cases

Put the idea to the test

New situations to think through using what you just discovered.

1 · Compare EfficiencyTwo algorithms explore the same graph. One follows a path deeply before backtracking, while the other explores all nearby vertices first. What factors would you examine to decide which approach is more suitable for the problem?
2 · Recognize the PatternA problem requires exploring every possible path from a starting point, including paths that may lead several steps deeper before another option is considered. What features would make a depth-first approach suitable?
3 · Spot the MisconceptionSomeone says, "DFS is better for finding the nearest target because it reaches a target as quickly as possible by going deep." What is wrong with this reasoning?
4 · Change the ConstraintsA DFS is exploring a very large graph, but the search can only keep a limited number of locations in memory. How might this constraint affect your choice of search strategy?
5 · Unfamiliar ApplicationA software project contains many files, and some files depend on others. You want to explore all dependencies starting from one file, following each dependency as deeply as possible before returning to another dependency. How could this approach help, and what could cause the search to revisit the same file?
6 · Maze to Graph
Look at the maze provided above. If you wanted to represent this maze as a graph, what would the rooms or positions represent, and what would the connections between them represent? Once represented as a graph, how could you explore it by following one path as deeply as possible before going back and trying another path?
